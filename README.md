# Бонусы и скидки в кассе

Таблицы программы лояльности лежат в той же базе, что и касса. Касса начисляет кэшбэк,
принимает оплату бонусами и применяет персональные скидки. CRM и бот только показывают результат
и сами дарят бонусы по рассылкам, триггерам и реферальной программе.

Для бонусов нужны 5 таблиц, писать надо только в одну - BonusTransactions. Для скидок ещё одна,
LoyaltyDiscountGrants. Остальные таблицы из `sql/Upgrade.sql` кассе не нужны.

Схема и описания колонок - в `sql/Upgrade.sql` и `sql/Descriptions.sql`, их можно накатить
на тестовую базу. Скрипты повторно запускаются без ошибок.


## Таблицы

### BonusTransactions - движения бонусов

Каждое начисление и каждое списание - отдельная строка. Отдельного поля с балансом нет,
баланс считается по строкам (см. ниже). Касса читает и пишет.

| Колонка | Тип | Описание |
|---|---|---|
| Id | bigint | ключ, автоинкремент |
| VisitorId | int | клиент, CashboxVisitor.IdVisitor |
| Amount | decimal(18,2) | плюс - начисление, минус - списание |
| Reason | int | причина: 0 вручную из CRM, 1 рассылка или триггер, 2 покупка (кэшбэк и оплата бонусами), 3 возврат покупки, 4 сгорание, 5 реферальная программа |
| SourceCampaignId | int, null | рассылка, которая начислила. Касса не заполняет |
| Comment | nvarchar(500), null | касса пишет номер заказа, например "Заказ 123456" |
| CreatedAt | datetime | время операции |
| ExpiresAt | datetime, null | когда сгорает. Пусто - не сгорает. Просроченные строки в баланс не входят |
| IsActive | bit | 1 - действует. 0 ставит CRM, если начисление отменили |

### LoyaltySettings - настройки программы

Одна строка, Id = 1. Меняется в CRM ("Настройки" - "Экономика бонусов"). Касса только читает,
лучше перед каждым чеком: администратор может поменять в любой момент.

| Колонка | Тип | Описание |
|---|---|---|
| BonusRate | decimal(9,2) | сколько рублей стоит 1 бонус. 1.00 - один к одному |
| MaxBonusPaymentPercent | int | какую часть чека можно оплатить бонусами, 0-100. 0 - оплата бонусами выключена |
| BonusLifetimeMonths | int, null | через сколько месяцев сгорает кэшбэк. Пусто или 0 - не сгорает |

Остальные колонки (MaxPromoMessages, PromoWindowDays, QuietFromHour, QuietToHour,
SurveyCooldownDays, AutoUpgradeTiers, GymBirthDateSync, UpdatedAt) - настройки рассылок и CRM,
кассе не нужны.

### LoyaltyTiers - уровни клиентов

Уровни и процент кэшбэка на каждом. Касса читает.

| Колонка | Тип | Описание |
|---|---|---|
| Id | int | ключ |
| Level | int | номер уровня: 1, 2, 3... На него ссылается LoyaltyProfiles.TierLevel |
| Name | nvarchar(100) | название: Базовый, Серебро, Золото |
| LtvThreshold | decimal(18,2) | с какой суммы покупок за всё время клиент попадает на уровень |
| RewardPercent | decimal(9,2) | процент кэшбэка на этом уровне |
| UpdatedAt | datetime | когда меняли |

### LoyaltyProfiles - профиль клиента в программе

Данные программы поверх карточки кассы. Строки может не быть - тогда клиент на уровне 1.
Кассе отсюда нужен только уровень.

| Колонка | Тип | Описание |
|---|---|---|
| VisitorId | int | клиент, CashboxVisitor.IdVisitor, он же ключ |
| TierLevel | int | уровень клиента, LoyaltyTiers.Level. 0 считать как 1 |

Остальные колонки (контакты, район, дата вступления и т.п.) заполняет CRM, кассе не нужны.
Уровень повышает система лояльности раз в час, касса его не меняет.

### TelegramLinks - кто подключил бота

Привязка Telegram к клиенту. Действующая привязка и есть участие в программе.
Касса читает, чтобы понять, начислять ли кэшбэк.

| Колонка | Тип | Описание |
|---|---|---|
| Id | bigint | ключ |
| VisitorId | int | клиент, CashboxVisitor.IdVisitor |
| TelegramChatId | bigint | чат, куда пишет бот |
| TelegramUsername | nvarchar(100), null | ник в Telegram на момент привязки |
| PhoneShared | nvarchar(30), null | номер, которым клиент подтвердил привязку |
| LinkMethod | int | как привязан: 0 неизвестно, 1 по телефону, 2 по коду из CRM |
| IsActive | bit | 1 - действует. Снимается, если клиент отвязался или заблокировал бота |
| LinkedAt | datetime | когда привязан |
| GymClientId | int, null | для тренажёрки, кассе не нужно |

### LoyaltyDiscountGrants - кому положена персональная скидка

Сама скидка (процент, услуга) лежит в кассовой cs_Discount, её создаёт система лояльности.
Здесь только список, кому она положена. Касса читает и отмечает использование.

| Колонка | Тип | Описание |
|---|---|---|
| Id | bigint | ключ |
| DiscountId | int | скидка, cs_Discount.ID |
| VisitorId | int | клиент, CashboxVisitor.IdVisitor. Для детских скидок - карточка ребёнка |
| IssuedAt | datetime | когда выдана |
| ExpiresAt | datetime, null | до когда действует для этого клиента. Пусто - без срока |
| UsedAt | datetime, null | когда использована. Заполняет касса |
| UsedOrderId | int, null | заказ, в котором использована, CashboxOrder.IdOrder. Заполняет касса |
| IsActive | bit | 1 - действует |
| SourceCampaignId | int, null | рассылка, которая выдала |
| SourceTriggerId | int, null | триггер, который выдал |
| Comment | nvarchar(500), null | пояснение для оператора |


## Как работать

### Баланс

Везде одна формула, в кассе тоже, иначе цифры в кассе и в боте разойдутся:

```sql
SELECT ISNULL(SUM(Amount), 0) FROM dbo.BonusTransactions
WHERE VisitorId = @visitor AND IsActive = 1 AND (ExpiresAt IS NULL OR ExpiresAt > GETDATE())
```

Все суммы бонусов - с точностью до копеек, округлять до 0.01.

### Кэшбэк

1. Начисляем только участникам программы:
   ```sql
   SELECT 1 FROM dbo.TelegramLinks WHERE VisitorId = @visitor AND IsActive = 1
   ```
   Нет строки - кэшбэк не начисляем.
2. Процент - RewardPercent уровня клиента (LoyaltyProfiles.TierLevel, нет профиля - уровень 1).
3. Считаем только с того, что заплачено деньгами. Часть чека, оплаченная бонусами, не считается.
   ```
   бонусов = ROUND(оплачено деньгами * RewardPercent / 100 / BonusRate, 2)
   ```
   Получилось 0 - строку не пишем.
4. Пишем строку: Amount = бонусов, Reason = 2, Comment = номер заказа,
   ExpiresAt = время покупки + BonusLifetimeMonths месяцев (пусто или 0 - ExpiresAt = NULL), IsActive = 1.

### Оплата бонусами

1. Сколько клиент может списать:
   ```
   максимум = MIN(баланс, ROUND(сумма чека * MaxBonusPaymentPercent / 100 / BonusRate, 2))
   ```
2. Списанные бонусы закрывают `бонусов * BonusRate` рублей, остальное - деньгами.
   С этой денежной части начисляется кэшбэк.
3. Списание пишем с минусом, Reason = 2, Comment = номер заказа. Как разбить на строки - ниже.

### Списание разбиваем по срокам

У каждого начисления свой срок сгорания. Если записать списание одной строкой без срока,
после сгорания баланс уйдёт в минус. Пример: +100 до 01.05, в апреле списали 100 одной
строкой без срока - с 01.05 у клиента -100.

Поэтому списываем начиная с тех начислений, что сгорают раньше, и пишем по строке на каждое,
с его ExpiresAt:

```
было:     +100 до 01.05, +50 до 01.08, +30 без срока
списать 120:
          -100, ExpiresAt = 01.05
          -20,  ExpiresAt = 01.08
```

### Возврат покупки

Кэшбэк, начисленный за эту покупку, снимаем отдельной строкой: Amount с минусом, Reason = 3,
ExpiresAt как у начисления, которое снимаем. Если клиент уже потратил эти бонусы и на счету
меньше, снимаем не больше остатка, чтобы баланс не ушёл в минус.

### Персональные скидки

Наши скидки в cs_Discount создаются с AutoOn = 0, сами они ни к кому не применяются. Применять
скидку можно, только если для клиента есть строка:

```sql
SELECT Id FROM dbo.LoyaltyDiscountGrants
WHERE DiscountId = @discount AND VisitorId = @visitor
  AND IsActive = 1 AND UsedAt IS NULL
  AND (ExpiresAt IS NULL OR ExpiresAt > GETDATE())
```

После продажи в этой строке ставим UsedAt = GETDATE() и UsedOrderId = номер заказа.
IsActive система лояльности снимет сама в течение 5 минут.

### Чего не делать

- Не удалять и не менять строки в BonusTransactions. Ошибку исправляем новой строкой.
- Не писать строки с Reason 0, 1, 5 - это подарки из CRM, рассылок и рефералки.
- Не менять TierLevel, LoyaltySettings, LoyaltyTiers, TelegramLinks - этим занимается CRM.
